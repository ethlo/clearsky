GitHub

Jira

This runs acli jira auth login --web, which opens the Atlassian login in your browser. Clearsky stores no Jira credentials.

Google Calendar

Option A, no new login: add your work Google account in your desktop's Settings → Online Accounts → Google, with Calendar switched on. Enter your work email below and save. Clearsky reads the calendar GNOME syncs.

Add a personal Google account in Online Accounts (Calendar only) to see family appointments here too. On a shared calendar (one not named after your address, like "Family"), events only take your time when you're invited, or when one of these names is in the title; the rest just show in the agenda.

Option B, iCal link (only if your admin allows it). You can use both; meetings are merged:

  1. Open Google Calendar settings.
  2. Under Settings for my calendars, click your calendar, then Integrate calendar.
  3. Copy Secret address in iCal format and paste it below.

Slack

  1. Create the Clearsky Slack app (pre-filled; pick your work workspace).
  2. Click Install to Workspace. Your admins may need to approve it.
  3. Under OAuth & Permissions, copy the User OAuth Token (xoxp-…) and paste it below.

General

Copilot

Defaults for a new chat. The pickers in a chat still change that chat.

Where a chat runs when it isn't about a PR or ticket. Chats about a PR or ticket run in that repo's clone, or the worktree with the PR's branch. Clearsky's own skills (stand-up, triage) are available only from the Clearsky folder.

Comma-separated, like ~/dev/kezzler, ~/dev/ethlo. Copilot can read and change files there, including worktrees next to your clones, without the "Access paths outside trusted directories" question. Commands and edits still follow the access mode. Empty means ~/dev. Running chats pick changes up on their next message.

In Ask and Assisted, commands like cat, ls, grep, find, sed -n, head and git status/log/diff/show run on their own when every part of the command only reads, and only inside the chat's folder and the folders above. Builds, tests, edits, git push, writing to files and anything Clearsky can't tell is safe still ask.

Command starts (comma-separated) that would otherwise ask, like moving a Jira ticket. Paths outside your folders still ask in Assisted.

Assisted runs everything in the chat's folder, the folders above and worktrees next to your clones (builds, tests, scripts like python3, local git including reset, rebase, apply and worktrees, gh and acli lookups, edits) and asks only before risky steps: git push, git clean, deleting unmerged branches or tags, rm (except under /tmp), installs (npm install, pip, npx), deploys and publishes, Jira and GitHub changes (acli create/edit/transition/comment, gh pr create/merge/comment, gh api writes), sudo, ssh, curl uploads, docker run/exec, scripts run by path, and anything outside your folders and /tmp. Add command starts here (comma-separated) to always be asked about them too.

With the sandbox on, Copilot and everything it runs can write only in the chat's folder, the folders above, ~/.copilot and /tmp, can't read ~/.ssh, ~/.aws, browser profiles or Clearsky's own settings, and can reach only the hosts below. That holds in every access mode, Full included. The Sandboxed access mode always runs in it, and then runs every step inside without asking; only pushes, Jira and GitHub changes, uploads, deploys and cloud tools ask. srt comes with Clearsky (Linux also needs bubblewrap, socat and ripgrep). Hosts are checked by name only: an allowed host can be written to as well as read. Inside it, git reaches GitHub over https with your gh login instead of ssh.

Comma-separated, wildcards like *.atlassian.net allowed. Empty means Copilot, GitHub and your Jira site. Add package registries (say repo.maven.apache.org, registry.npmjs.org) if builds need them.

Modules

What each part of Clearsky holds and talks to. Saved secrets are never shown, only whether one is there. Each source gets only its own settings, and a source that lists its hosts can reach only those through Clearsky.
